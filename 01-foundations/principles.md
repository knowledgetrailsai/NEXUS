# Principles

`Home › 01-foundations › Principles`

## 1. Function first, domain second

The same automation pattern (e.g., document review, triage, drafting, forecasting) recurs across industries. Describing it once at the function level, then noting domain variants, avoids nine near-duplicate descriptions of the same idea. See [02-functions](../02-functions/claims-management.md).

## 2. Rate automation depth explicitly, don't assume "full autonomy"

Not every opportunity should be autonomous end-to-end. Every use case in this repository is rated against the [Agentic Automation Spectrum](agentic-automation-spectrum.md) — from simple co-pilot assistance through to bounded autonomy — so the realistic starting point is clear, not just the aspirational end state.

## 3. A use case here is a hypothesis, not a business case

Every entry names a plausible **Value Signal** — the kind of value a real deployment might target — but this is explicitly *not* a substitute for the rigor of [oasis-fulcrum](https://github.com/knowledgetrailsai/oasis-fulcrum)'s Outcome & Value Definition Sheet. See [Value Signal, not a Value Case](#value-signal-not-a-value-case) below.

## 4. Name the risk, don't design the control

Each use case flags key risks in plain terms (data sensitivity, decision reversibility, regulatory exposure) so a reader knows where to look closer. Full control design belongs in [Responsible-AI](https://github.com/knowledgetrailsai/Responsible-AI) — this repository points at the risk, it doesn't resolve it.

## 5. Grid cells are directional, not prescriptive

Marking a function × domain cell as "Core" in [the grid](../04-grid/opportunity-grid.md) means the pattern is well-evidenced there — not that every organization in that domain should build it. Local context always overrides a general grid.

### Value Signal, Not a Value Case

Each use case names:
- A plausible **outcome definition** (what "success" would look like)
- A plausible **value basis** (cost avoided, revenue influenced, time saved — the categories, not committed figures)

This is a starting hypothesis for [oasis-fulcrum Phase 1](https://github.com/knowledgetrailsai/oasis-fulcrum) — it is deliberately not a committed ROI number, because that requires the sourced, sign-off-backed rigor of the Outcome & Value Definition Sheet, which this repository cannot do generically.
