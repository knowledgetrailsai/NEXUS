## How to Read a Cell

Every cell links back to its function file (row) and domain file (column), both of which link forward to any detailed [use case](../05-use-cases/) that exists for that intersection. "Applies" and "Limited" cells without a named use case are gaps in this catalog, not gaps in reality — see [CONTRIBUTING.md](../CONTRIBUTING.md).

## Using the Grid

## Cell Evidence Standard

Cell labels communicate fit, not certainty. **Core** means a repeatable workflow, accessible source data, a plausible L1–L2 starting point, and a named use case. **Adaptable** means the pattern is credible but domain controls, terminology, or integrations materially change the design. **Limited** means the opportunity is indirect, highly context-dependent, or outside this catalog's safe starting posture.

1. **Function-first scan** — read across a row to see where a function's pattern is strongest.
2. **Domain-first scan** — read down a column to see which functions matter most in your industry.
3. **Prioritize** — once you've identified candidate cells, use the [Prioritization Framework](prioritization-framework.md) to sequence them.
